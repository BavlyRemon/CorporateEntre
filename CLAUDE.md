# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A research workspace whose primary deliverable is a comparative paper on corporate entrepreneurship across Amazon, NVIDIA, Shell, and Chevron, built from a 28-letter corpus (7 CEO/shareholder letters per company). The core is still Python scripts in `00_admin/` that rebuild artifacts from source files (no tests, no linter for that part).

It now also contains three React/Vite apps under `00_admin/` (see **Apps** below): an analysis dashboard, a slide presentation (deployed to GitHub Pages), and a letter-review tool. These visualise the generated data — they never recompute it.

## Folder pipeline

The numbered top-level directories are a strict pipeline; later stages consume earlier ones.

- `00_admin/` — build scripts, source ledger (`sources_master.csv`), method notes, research log
- `01_raw_sources/{amazon,nvidia,shell,chevron,industry_sources}/` — downloaded HTML/PDF originals
- `02_extracted_text/` — machine-readable text. The canonical analysis input lives in `02_extracted_text/selected_ceo_letters/` with manifest `selected_ceo_letters_manifest.csv`
- `03_screening_and_selection/` — timelines, candidate-year tables, selection memos, CEO-letter availability audit
- `04_quant_framework/keyword_lists/` — lexical dictionary CSVs (`theme_dictionary_master.csv`, `explore_exploit_dictionary.csv`). **These are generated, not authored** — see "Lexicon" below. The canonical dictionary is `00_admin/lexicon.py`.
- `05_outputs/` — generated CSV tables (`tables/`), markdown briefs (`company_briefs/`, `methodology_briefs/`, `industry_comparison/`), and final PDF/DOCX reports
- `06_appendices/` — source cards, download manifest, citation backup

## Build scripts

All four scripts use `ROOT = Path(__file__).resolve().parents[1]`, so paths are repo-relative regardless of working directory. Run from the repo root.

| Script | What it does | When to run |
| --- | --- | --- |
| `00_admin/build_research_workspace.py` | Downloads official sources (Amazon letters, NVIDIA IR PDFs, Shell reports, SEC 10-Ks), extracts text, writes `sources_master.csv`, timelines, dictionary, pilot counts, memos, README. Network-bound. Requires `requests`, `beautifulsoup4`, `pypdf`. | Initial bootstrap or to refresh raw sources |
| `00_admin/build_milestone_analysis_package.py` | Reads the selected-letter corpus, regenerates all `05_outputs/tables/*.csv` (theme counts, explore/exploit ratios, IPM matrix, comparative matrix), **regenerates the two `04_quant_framework/keyword_lists/*.csv` dictionaries from `lexicon.py`**, and rewrites the `05_outputs/company_briefs/*.md` + `methodology_briefs/*.md` + `industry_comparison/*.md`. Stdlib only (imports `00_admin/lexicon.py` + `00_admin/stemmer.py`). | After editing the corpus or `lexicon.py` |
| `00_admin/build_integrated_paper_pdf.py` | Renders `05_outputs/corporate_entrepreneurship_integrated_analysis_draft.pdf` from the generated tables. Stdlib only (custom `SimplePDF`). | After the milestone package |
| `00_admin/build_submission_ready_report_pdf.py` | Renders the polished `corporate_entrepreneurship_submission_ready_report.pdf` and `.docx` plus appendix CSVs. Stdlib only. | Final report build |

Run order for a full rebuild: `build_research_workspace.py` → `build_milestone_analysis_package.py` → `build_integrated_paper_pdf.py` → `build_submission_ready_report_pdf.py`.

## Critical: scripts overwrite hand-edited markdown

`build_milestone_analysis_package.py` writes most files in `05_outputs/company_briefs/`, `05_outputs/methodology_briefs/`, and `05_outputs/industry_comparison/` from string literals embedded in the script. Re-running it will clobber any manual edits to those `.md` files. If the user has hand-edited a brief, do not re-run the builder without confirming — instead, edit the source string inside the script so the change survives a rebuild.

The same applies to the top-level `README.md`, which is generated by `build_research_workspace.py`'s `write_readme()`.

## Data conventions

- **Unit of analysis**: one selected leadership letter per company-year. Boundaries (line ranges in the source extract) are recorded in `02_extracted_text/selected_ceo_letters/selected_ceo_letters_manifest.csv` — do not re-derive them, read from the manifest.
- **Counts are normalized per 1,000 words** of letter body, after stripping the extraction header. See `strip_header()` and `per_1000()` in `build_milestone_analysis_package.py`.
- **Lexical matching is stem-aware**, case-insensitive (changed 2026-05-13). The matcher lives in `00_admin/lexicon.py` and uses a pure-Python Porter stemmer (`00_admin/stemmer.py`). See "Lexicon" below — do **not** add terms by editing the CSVs.
- **Selected years are fixed** (Amazon: 1997, 2016, 2020–2022, 2024–2025; NVIDIA: 2017–2018, 2020–2023, 2025; Shell: 2014–2016, 2020, 2022, 2024–2025; Chevron: 2013, 2018, 2020–2024). Changing the set means updating the manifest, the selection memos, and rerunning the milestone package.
- **Citations** in the briefs point to the extracted letter files, not the original PDFs. Official URLs/access dates live in `sources_master.csv` and the manifest.

## Lexicon (keyword dictionaries + matcher)

Changed 2026-05-13. The old whole-word regex matcher is gone.

- **`00_admin/lexicon.py`** is the canonical source for `IPM_TERMS`, `CROSS_TERMS`, and `THEME_SUBTHEMES`. Each entry is either a literal phrase string (multi-word / contains punctuation → whole-word match) or a dict `{base, aliases?, excludes?, stem?}`.
- **`00_admin/stemmer.py`** is a pure-Python Porter (1980) stemmer, stdlib-only. A token counts if its stem ∈ `{stem(base)} ∪ {stem(alias_i)}` minus surface forms in `excludes`. `stem: False` opts an entry out of stemming (used for `integrity`, `values` where Porter collapses unrelated words).
- The two CSVs in `04_quant_framework/keyword_lists/` are **regenerated from `lexicon.py`** by `build_milestone_analysis_package.py` (`write_dictionary_csvs()`). Editing them by hand has no effect — the next build overwrites them. Edit `lexicon.py` instead.
- `build_submission_ready_report_pdf.py` also imports `lexicon.py` for its appendix keyword tables, so both build scripts stay consistent.
- Watch for Porter stem collisions when adding terms (e.g. `decisive`/`decision`, `experiment`/`experience`, `productive`/`production`, `engineer`/`engine`, `founder`/`found`). Add the bad surface forms to that entry's `excludes`.

### Keyword review workflow

`00_admin/keyword_review_notes.md` is a scratchpad: add an H2 header `## <category>/<base>` (e.g. `## explore/innovate`) with free-form notes underneath. The dashboard's **Lexicon** page renders each note next to its dictionary entry, with corpus hit counts. To apply notes, translate them into `lexicon.py` edits, then rerun the pipeline. Unmatched note headers surface as a warning on the Lexicon page.

## Apps

Three independent React 18 + Vite + Tailwind apps under `00_admin/`. Each has its own `package.json`; run `npm install` once per app.

| App | Path | Run | Port | Purpose |
| --- | --- | --- | --- | --- |
| **Dashboard** | `00_admin/dashboard/` | `python build_dashboard_data.py` then `npm run dev` | 5173 | Browse letters, financials, lexical analysis, eras, the Lexicon page, briefs. Reads a generated static `src/data/dataset.json` — no backend. |
| **Presentation** | `00_admin/presentation/` | `npm run dev` | 5174 | The 10-slide deck (framer-motion, staged reveals, per-company branding, pulled quotes). Deployed to GitHub Pages. |
| **Review app** | `00_admin/review_app/` | `node server.js` (Express) + `npm run dev` (Vite) | 3001 (API) / 5173 (Vite) | Letter-by-letter extraction review tool. Express on 3001 persists review state to disk; Vite proxies `/api` to it. Vite's 5173 collides with the dashboard's — run only one at a time, or change a port. |

**Dashboard data refresh:** `cd 00_admin/dashboard && python build_dashboard_data.py` reads `05_outputs/tables/*.csv`, the manifest, the markdown briefs, and (via `lexicon.py`) computes per-entry corpus hit counts + parses `keyword_review_notes.md`. It writes `src/data/dataset.json` and `src/data/briefs/*.md`. Run it after any pipeline rebuild so the dashboard reflects new numbers. These generated files **are** committed (so the deployed/cloned app works without Python).

**Full rebuild order including apps:** `build_research_workspace.py` → `build_milestone_analysis_package.py` → `build_integrated_paper_pdf.py` → `build_submission_ready_report_pdf.py` → `00_admin/dashboard/build_dashboard_data.py`.

## Scope guardrails (from `method_notes.md` and `README.md`)

- The quantitative framework is a structured lexical screen, not a substitute for interpretation. Terms like "platform," "leadership," "growth," "resilience" mean different things in tech vs. energy contexts — flag ambiguity rather than over-claim from counts.
- Pilot counts in `04_quant_framework/pilot_counts/` are noise tests on uncleaned text; the authoritative counts are the ones in `05_outputs/tables/` produced from the cleaned selected-letter corpus.
- Treat copyright carefully: briefs use short paraphrased evidence, not extended quotes from the source letters.
